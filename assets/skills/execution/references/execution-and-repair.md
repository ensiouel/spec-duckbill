# Execution and Repair

## Execute

Use the explicitly requested task after confirming its dependencies are completed. Inspect existing code before editing. Implement the smallest coherent change that satisfies the task, then run its listed checks and relevant project tests.

## Repair

Treat feedback as a correction to one task's implementation. If it changes product intent, route it to specification refinement. If it changes the technical approach or task breakdown, route it to plan refinement.

Set `**Status:** completed` only after all required checks pass. Otherwise keep it `pending` and explain what remains. Stop after one task.
